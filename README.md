# 배당 시세 자동 수집기

[월배당 포트폴리오 설계실](https://claude.ai/artifact/UfeAKhsgnndimbTXVVGpT4) 이 읽어가는 시세 데이터를
매일 자동으로 갱신하는 저장소입니다.

## 왜 이런 게 필요한가

설계실 페이지는 보안 정책상 야후 파이낸스 같은 곳에 **직접 요청을 보낼 수 없습니다.**
`fetch` 가 전부 막혀 있고, 스크립트도 몇몇 CDN 에서만 불러올 수 있습니다.

실제로 테스트해 본 결과는 이렇습니다:

| 경로 | 결과 |
|---|---|
| `cdn.jsdelivr.net/gh/…/data.js` 를 `import()` | **통과** |
| `cdn.jsdelivr.net/npm/…/+esm` | 통과 |
| `/gh/…/data.json` + import attributes | 차단 |
| jsDelivr 로 `fetch()` | 차단 |
| 야후로 `fetch()` 또는 `<script src>` | 차단 |

그래서 **GitHub 에 올려둔 `.js` 파일**이 유일하게 통하는 통로입니다.
이 저장소가 매일 야후에서 시세를 받아 `data.js` 로 커밋해두면,
페이지는 jsDelivr 를 통해 그 파일을 읽기만 하면 됩니다.

`.json` 이 아니라 `.js` 여야 하고, 반드시 `export default {...}` 형태여야 합니다.

## 설치

1. **공개(Public) 저장소**를 하나 만듭니다. 비공개면 jsDelivr 가 읽지 못합니다.

2. 이 파일들을 그대로 올립니다.

   ```
   collect.py                    수집 진행
   sources.py                    외부 소스 8곳 정의
   merge.py                      교차검증·합의 로직
   tickers.txt                   수집할 종목
   data.js                       결과 (페이지가 읽는 파일)
   .github/workflows/daily.yml   자동 실행
   README.md
   ```

3. **Settings → Actions → General → Workflow permissions** 를
   **Read and write permissions** 로 바꾸고 저장합니다.
   이걸 빠뜨리면 수집은 되는데 커밋 단계에서 실패합니다.

4. **Actions** 탭 → **시세 갱신** → **Run workflow** 로 한 번 돌려봅니다. 2~3분 걸립니다.

5. 설계실 페이지 1번 섹션의 **시세 자동 갱신** 칸에 `사용자명/저장소명` 을 넣습니다.
   초록색 **자동 연동** 배지가 뜨면 끝입니다.

## 동작

`.github/workflows/daily.yml` 이 평일 네 번 돕니다. 정각을 피한 시각입니다.
GitHub 예약 실행은 정각에 요청이 몰려 자주 밀리거나 아예 빠지기 때문입니다
(실제로 16:00 KST 에 걸어둔 첫 예약 실행이 통째로 누락됐습니다).

| UTC | 한국시간 | 무엇 |
|---|---|---|
| 21:37 | 06:37 | 미국장 마감 후 |
| 23:43 | 08:43 | 위 실행이 빠졌을 때 대비 |
| 07:17 | 16:17 | 국내장 마감 후 |
| 10:23 | 19:23 | 위 실행이 빠졌을 때 대비 |

바뀐 내용이 있으면 `data.js`, `universe/`, `yahoo_cache.json` 을 커밋하고 jsDelivr 캐시를 두 번 비웁니다.
봇이 계속 커밋하므로, 60일간 활동이 없으면 예약을 끄는 GitHub 규칙에도 걸리지 않습니다.

## 야후는 비상용입니다

야후 파이낸스는 키 없이 쓸 수 있지만 공식 API가 아니고(2017년 종료),
요청이 몰리면 `HTTP 429 Too Many Requests` 로 막힙니다. 그래서 기본 수집은
**사용량 제한이 없는 GitHub 저장소와 Hugging Face 데이터셋만으로** 합니다.
야후는 이 소스들로 주가나 분배금을 못 채운 종목에만 부릅니다.
2026-09-21 기준 103종목 전부가 야후 없이 채워져서, 평소에는 야후를 한 번도 부르지 않습니다.

`daily.yml` 의 `USE_YAHOO` 로 바꿀 수 있습니다.

| 값 | 동작 |
|---|---|
| `fallback` (기본) | 못 채운 종목에만 야후 호출 |
| `off` | 야후를 전혀 부르지 않음 |
| `on` | 전 종목을 야후에서도 받아 교차검증 표로 사용 (429 위험) |

**대가:** 야후를 빼면 미국 ETF 80종목 중 대부분이 ttokjaeTV 한 곳에만 기댑니다.
페이지 표에서 회색 `1` 배지로 표시됩니다. 주가는 야후를 넣었을 때와 차이가 없었고(중앙값 0.00%),
분배금은 ttokjaeTV 배당 파일이 주 1회 갱신이라 월배당 종목 일부가 3~8% 차이 났습니다.
교차검증이 더 중요하면 `on` 으로 바꾸세요.

## 목록에 없는 종목도 매일 갱신됩니다 (`universe/`)

수집기는 매 실행마다 **미국 약 12,000종목과 국내 ETF 약 1,200종목 전체**의 주가·분배금을
`universe/` 폴더에 첫 글자별로 나눠 씁니다 (`us-A.js` … `us-Z.js`, `kr.js`, 파일당 최대 약 90KB).
페이지에서 목록에 없는 종목을 검색하면 그 글자 파일 하나만 불러와 주가·분배금·종목명을
자동으로 채우고, 추가한 뒤에도 매일 여기서 갱신됩니다. **`tickers.txt` 를 고칠 필요가 없습니다.**
국내 ETF 는 총보수와 국내/해외 구분까지 들어 있어 과세 유형도 자동으로 정해집니다.
이 파일의 값은 ttokjaeTV(+ Kimjaeohong / iankim1306) 기준이며, `tickers.txt` 종목처럼
8개 소스 교차검증을 거치지는 않습니다.

## 야후 순환 캐시 (`yahoo_cache.json`)

야후에 103종목을 한꺼번에 물으면 429 로 막힙니다. 그래서 실행마다 **가장 오래된 15종목만**
물어 `yahoo_cache.json` 에 쌓고, 나머지 종목은 이 캐시의 분배금(최근 10일 이내)을
두 번째 소스로 씁니다. 하루 두 번 실행이면 3~4일에 한 바퀴 돕니다. 야후가 막으면 그 자리에서 멈춥니다.
결과적으로 **모든 종목의 분배금이 소스 2개 이상**으로 교차검증됩니다.
`daily.yml` 의 `YAHOO_ROTATE` 로 한 번에 묻는 수를 바꿀 수 있습니다(0 이면 끔).

## 여러 소스를 섞는 이유

한 곳만 믿으면 그곳이 틀렸을 때 알 방법이 없습니다. 그렇다고 순서대로 폴백만 시키면
세 번째 소스가 이상한 값을 줘도 그대로 들어갑니다.

그래서 수집기는 **받을 수 있는 모든 소스를 받아 중앙값으로 합의**합니다.

| 소스 | 내용 | 갱신 |
|---|---|---|
| ttokjaeTV `us_prices.csv` | 미국 주가 12,292종 | 장중 30분마다 |
| ttokjaeTV `us_dividends.csv` | 미국 분배금 · 지급월 6,635종 | 주 1회 |
| ttokjaeTV `etf_prices.csv` | 국내 ETF 주가 1,171종 | 장중 30분마다 |
| ttokjaeTV `etf_tax_base.json` | 국내 ETF 분배금 · 과세표준액 954종 | 수시 |
| Kimjaeohong `us_dividends.json` | 미국 주가 · 분배금 112종 | 매일 |
| holaclea `schd-payments` | SCHD, Schwab 공식 공시 | 수동 |
| iankim1306 `dividendcal-data` | 국내 ETF 분배금 3,641건 (DART 공시) | 매일 |
| [defeatbeta-api](https://github.com/defeat-beta/defeatbeta-api) | 미국 개별주 주가 · 배당 (Hugging Face 데이터셋, DuckDB 조회) | 매일 |

### defeatbeta-api 에 대해

야후 데이터를 Hugging Face 데이터셋으로 정리해 두고 DuckDB 로 조회하는 라이브러리라
**레이트리밋(429)을 받지 않습니다.** 대신 **개별 주식 데이터셋이라 ETF 가 거의 없습니다.**
실측 결과 이 저장소의 103종목 중 **7종목만**(O · ARCC · MAIN · AGNC · STAG · WPC · VICI) 들어 있고,
SCHD · JEPI · QYLD 같은 배당 ETF 와 국내 종목은 없습니다. 그래서 야후를 대체하지 않고
**소스 하나로 추가**했습니다. 7종목의 분배금은 6개가 기존 합의값과 소수점까지 일치했습니다.

설치 실패나 조회 실패가 나도 수집 전체는 멈추지 않고 이 소스만 건너뜁니다.

합의 규칙은 `merge.py` 에 있습니다.

1. 직전 `data.js` 값을 기준선으로 두고, **25% 넘게 벗어난 값은 버립니다.**
   티커가 겹치는 다른 시장 상품이 섞여 들어오는 사고를 막습니다.
   (유럽 UCITS 데이터셋에서는 `SPYI` 가 전혀 다른 펀드입니다.)
2. 남은 값들의 **중앙값**을 씁니다. 한 소스가 틀려도 끌려가지 않습니다.
3. 소스끼리 **3% 넘게 갈리면 표시**합니다. 페이지 표에 `⚠` 로 뜹니다.
4. 기준선이 낡아서 전부 버려질 경우, 소스 둘 이상이 서로 동의하면 그쪽을 받아들입니다.

결과에는 종목마다 `pxSrc` / `ttmSrc` 로 **어느 소스가 그 값을 뒷받침했는지** 기록됩니다.

### 소스 독립성에 대한 경고

ttokjaeTV · Kimjaeohong · yfinance 는 **전부 야후 계열**입니다. 값이 맞아떨어지는 건
"서로 검증됐다"기보다 **"같은 상류를 봤다"** 에 가깝습니다. 야후가 틀리면 셋 다 틀립니다.

진짜로 독립적인 건 두 개뿐입니다.

- `holaclea` — Schwab 운용사 공식 공시 (SCHD 한 종목이지만, 나머지가 전부 틀렸을 때 알아챌 수 있는 유일한 장치)
- `iankim1306` — DART 전자공시 (국내 ETF)

## 종목 추가

`tickers.txt` 에 한 줄 추가하면 됩니다.

```
SCHG     # Schwab 미국 대형 성장주
069500   # KODEX 200
```

국내 종목은 6자리 코드만 적으면 `.KS` 가 자동으로 붙습니다.

## data.js 형식

```js
export default {
  "generated": "2026-09-17T15:20:26+00:00",
  "source": "Yahoo Finance via yfinance",
  "count": 103,
  "failed": [],
  "quotes": {
    "SCHD": { "t":"SCHD", "sym":"SCHD", "px":33.84, "cur":"USD",
              "ttm":1.048, "n":4, "xm":[3,6,9,12] }
  }
};
```

| 필드 | 뜻 |
|---|---|
| `px` | 현재가 (해당 종목의 통화 기준) |
| `cur` | `USD` 또는 `KRW` |
| `ttm` | 최근 1년 주당 분배금 합계 |
| `n` | 그 1년간 지급 횟수 = 연 지급 횟수 |
| `xm` | 배당락이 있었던 월 — **지급월과는 한 달 차이가 날 수 있습니다** |

## 분배금 계산을 358일로 자르는 이유

배당락일은 해마다 며칠씩 앞당겨집니다. 그래서 오늘부터 정확히 365일을 거꾸로 세면
작년 같은 분기의 배당이 한 번 더 걸려 분배금이 부풀려집니다.
반대로 오늘 기준으로만 세면 이번 분기 배당이 아직 안 나온 종목은 한 번 모자랍니다.

그래서 **가장 최근 배당락일에서 358일을 거슬러** 셉니다.
103개 종목을 손으로 검증한 값과 대조해 폭을 정했습니다.

| 창 | 10% 넘게 틀린 종목 |
|---|---|
| 365일 | 25개 |
| 360일 | 2개 |
| **358일** | **2개** |
| 350일 | 4개 |

358일에서 남은 2개는 `STAG`(2026년 1월 월배당→분기배당 전환)와
`HDV`(2026년 7월 분기배당→월배당 전환)로, 주기가 바뀌는 중이라 어떤 창으로도
한 해치를 딱 떨어지게 셀 수 없는 종목들입니다.

## 안전장치

- 한 종목도 못 받으면 `data.js` 를 덮어쓰지 않고 중단합니다.
- 수집 결과가 직전보다 40% 넘게 줄면 기존 파일을 지킵니다.
- 내용이 안 바뀌었으면 커밋하지 않습니다.
- 일부 종목만 실패하면 `failed` 배열에 남기고 나머지는 정상 반영합니다.

## 알아둘 점

- 값은 **전일 종가**입니다. 장중 실시간 호가가 아닙니다.
- 야후 데이터는 공식 자료가 아닙니다. 세금 신고나 정산 목적으로 쓰지 마세요.
- 페이지는 저장소가 없어도 내장 데이터로 동작합니다. 연동은 어디까지나 선택입니다.
- 저장소가 며칠 이상 갱신되지 않으면 페이지가 경고를 띄웁니다.
